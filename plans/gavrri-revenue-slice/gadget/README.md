# Sales Desk Gadget — local synthetic demonstration

The Gadget delegates reads and proposed writes to the explicitly connected local `SALES` Gatekeeper. Company, candidate, contact permission, event, contract, amount, next action and explicit company linking entries are proposals: the OS approval queue must approve them before they are saved. A proposal response is not proof of persistence. Check the OS activity queue and refresh to read the resulting data. Evidence and version requirements apply; contact permission cannot override refusal, unknown receipt, or prior-contact protections. Linking preserves the refusal of either identity across all offers. There is no email or form sending.

The initial company overview uses a horizontally scrollable comparison table for company × offer × motion, supports search, offer and status filters, due actions, ordering and history details. Each page contains at most 100 entries. The Gadget fetches all candidate pages before search, filters and sorting, and all event pages before deriving the latest status. Pages use rowid insertion order and capture an upper bound at the start; records appended later appear on refresh. Candidate field edits are not an atomic snapshot. Failed pages never count as complete. Cursor tokens are session-local and bound to the account, query and candidate; reconnecting requires a fresh read. Approval state is not available through this session API and is shown as unconfirmed. The dashboard shows applicable campaign limits, monthly revenue and payment and a separately scaled MRR trend. Confirmed entries are not proof of complete coverage; unknown is not zero. Currency is never converted. The read-only migration preview uses one embedded synthetic sample; there is no file selection, paste, or import action.

Only the `demo` dataset is supported by this local Gatekeeper. Switching to a rejected scope clears prior values. The source files here are copied into a Gadget when a local blueprint is created; editing these files later does not update an existing Gadget. Create a fresh local demonstration using the parent README after code changes.

This is not a deployable or production membership design. Do not connect real data. An isolated RPC setup helper is in `setup-local.mjs`; it requires a disposable OS and database on `127.0.0.1:8788`. See the parent README for local setup.
